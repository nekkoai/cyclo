# `project.cyclo` format

`project.cyclo` is the run definition for one agentic project. It names and
describes the work, selects one or more team repositories, and grants every
selected team access to named host directories.

```text
# Whole-line comments and blank lines are ignored.
name core-et-uart
description Integrate and verify a reusable UART IP in OpenHW CORE-ET.

context <<PROJECT_CONTEXT
`core-et` is the writable implementation repository.
`uart-ip` is a separately versioned writable IP repository.
`specifications` contains normative read-only documentation.
PROJECT_CONTEXT

team ../teams/jon-rtl ro
team ../teams/rtl-auditor ro

mount core-et ../sources/core-et rw
mount uart-ip ../sources/uart-ip rw
mount specifications ../references/specifications ro
```

Validate and run it:

```sh
cyclo validate /path/to/project.cyclo
cyclo run /path/to/project.cyclo
```

Or generate it:

```sh
cyclo project init /path/to/project.cyclo --context /path/to/context.md --team /path/to/jon-rtl ro --mount core-et /path/to/core-et rw --mount uart-ip /path/to/uart-ip rw --mount specifications /path/to/specifications ro
```

## Container view

Each `team` line creates one durable Cyclo instance and one team component in
the installation-wide DComp system. The example produces
`core-et-uart-jon-rtl` and `core-et-uart-rtl-auditor`.

Each component has its own AgentWS queue, Pi state, team mount, Provider link,
and optional dashboard port. All selected teams receive the same project
mounts:

```text
/workspace/core-et
/workspace/uart-ip
/readonly/specifications
```

Only `rw` mounts appear below `/workspace`; they are the writable projects.
Only `ro` mounts appear below `/readonly`; they are supporting inputs. Several
`rw` lines deliberately represent several projects. Cyclo does not designate a
special primary repository.

The selected team repository appears at `/team`, read-only or writable
according to its `team` line.

## Agent project context

Cyclo materializes a read-only `/agentws/project.cyclo` for every instance. It
retains the authored name, description, and context but replaces host paths
with their container paths:

```text
# Generated by Cyclo for this team container.
# Team and mount paths are container paths; host paths are omitted.
name core-et-uart
description Integrate and verify a reusable UART IP in OpenHW CORE-ET.
context <<CYCLO_CONTEXT
`core-et` is the writable implementation repository.
`uart-ip` is a separately versioned writable IP repository.
`specifications` contains normative read-only documentation.
CYCLO_CONTEXT

team /team ro

mount core-et /workspace/core-et rw
mount uart-ip /workspace/uart-ip rw
mount specifications /readonly/specifications ro
```

The generic AgentWS protocol requires agents to read this file before touching
project sources. It is project knowledge, not a prompt fragment duplicated into
every job. Host filesystem paths are omitted.

AgentWS code and tools are baked into the team image. Cyclo bind-mounts only the
three durable queue directories, Pi state, this generated project file, the
team repository, and declared project directories.

Authored description and context are copied literally. Do not put credentials
or other secrets in them.

## Grammar

The format is UTF-8, line-oriented, and deliberately has no quoting or shell
expansion:

```text
name <project-name>
description <free text to end of line>
context <<MARKER
<literal project context>
MARKER
team <directory> <ro|rw>
mount <mount-name> <directory> <ro|rw>
```

Rules:

- Exactly one `name` is required. It contains 1–64 lowercase letters, numbers,
  dots, underscores, or hyphens and begins with a letter or number.
- Exactly one nonempty `description` is required. It consumes the rest of the
  line; `#` has no inline-comment meaning there.
- At most one `context` block is accepted. The marker begins with a letter,
  then contains at most 31 more letters, numbers, or underscores. Its closing
  line must match exactly. Leading and trailing blank lines are removed; an
  empty block is rejected.
- One or more `team` lines are required. Team paths and case-insensitive final
  directory names must be unique. Every selected team must be a valid Git
  repository whose root is the selected directory.
- One or more `mount` lines are required. Mount names and resolved paths must be
  unique.
- A `ro` team line protects the team repository from agent writes. A `rw` team
  line intentionally permits self-modification.
- A `rw` mount becomes `/workspace/<name>`. A `ro` mount becomes
  `/readonly/<name>`.
- Blank lines and lines whose first non-whitespace character is `#` are
  ignored. Inline comments are not syntax.
- Relative paths resolve from the directory containing `project.cyclo`.
  Absolute paths are accepted. Every path must already be a directory.
- Path tokens cannot contain whitespace, `~`, comma, quotes, or backslash.
  There is no home expansion.
- Team and mount trees must not overlap one another.
- The project file must be a regular non-symlink file no larger than 1 MiB.
  Tabs and other control characters are rejected.
- Unknown directives fail closed. `mcp` is currently rejected because Cyclo
  0.2 does not implement MCP attachment.

Cyclo hashes the validated semantic definition, including resolved paths,
order, modes, description, and context. That generation is recorded in each
instance.

## Mount authority

Before Cyclo emits a DComp bind, it resolves every team and project path to a
canonical directory and rejects any path that overlaps:

- another selected team or project tree;
- the Cyclo state root;
- installed Cyclo code;
- the selected `host.conf`;
- the DComp executable;
- the host Pi configuration;
- `/proc`, `/sys`, `/dev`, or `/run`; or
- a known Docker socket.

Initial run also records each source's device and inode after validation and
checks them again before committing the launch. Every later global apply
re-resolves persisted source paths and repeats the authority checks.

This prevents accidental expansion of agent filesystem authority. It does not
make declared readable data confidential from the team or its selected model
Provider.

## Run options

The project file owns team and mount authority. The supported runtime options
are:

```text
--image IMAGE
--offline
--host IPV4
--port PORT
--verbose
--foreground
```

`--image` selects one operator-built compatible team image for all teams in the
definition and bypasses team Dockerfiles. Cyclo validates but does not build
that image.

Without `--image`, Cyclo invokes Docker build for its common team image. A team
with a Dockerfile receives a derived build with the exact common image as
`CYCLO_TEAM_BASE`. Docker owns context filtering and layer-cache reuse.

`--offline` removes a team's direct external network and AgentWS dashboard
publication while preserving its private DComp Provider link.

`--host` is a literal IPv4 bind address and defaults to `127.0.0.1`. `--port 0`
asks Docker for a dynamic port. A fixed `--port` and `--foreground` are accepted
only for single-team projects; a fixed port is incompatible with `--offline`.

## Persistence and updates

`cyclo run` refuses to overwrite an existing instance ID. Use the lifecycle
commands instead:

```sh
cyclo stop INSTANCE
cyclo start INSTANCE
cyclo refresh
cyclo forget INSTANCE --confirm INSTANCE
```

An instance records `running` or `stopped` intent, an immutable team image ID,
the validated team/project generation, the generated container project view,
and mount source facts. It does not record container or network lifecycle
state; DComp owns those facts.

`start` uses the persisted instance definition. `refresh` reparses the recorded
project file for every running instance, validates current team sources, runs
the required image builds, updates instance records, and applies the new global
system.
Stopped instances are not refreshed.

`cyclo stop /path/to/project.cyclo` stops the instances selected by the current
definition. If an instance's team line was removed, stop that persisted
instance by ID.

If system application fails after new running intent is persisted, the instance
remains visible. Correct the configuration or component and use `cyclo repair`;
Cyclo does not hide the failure or invent a different Provider route.
